Metropolis algorithm

As we learned in class on Thursday, the Metropolis algorithm requires a symmetric proposal density \(J(y \mid x) = J(x \mid y)\). A generalization of the Metropolis algorithm which doesn’t require symmetry is called the Metropolis-Hastings (MH) algorithm. All we do is modify the acceptance probability \(h(x, y)\) for a proposed \(y\) evaluated at the current value \(x\).

In the Metropolis algorithm, for a target density \(\pi(x)\) we have: \[ h(x,y) = \min(\pi(y) / \pi(x), 1) \] The Metropolis-Hastings algorithm now has: \[ h(x,y) = \min\left(\frac{\pi(y)J(x \mid y)}{\pi(x) J(y \mid x)}, 1\right) \]

We will denote fixed quantities as lower-case numbers, while upper case will represent random variables.

Algorithm 1 (Metropolis-Hastings) For a given \(x_1\), \(N\), and target density \(\pi(x)\):

  1. For \(t \in \{1, \dots, N\}\)
    1. Generate \(Y_t \sim J(y \mid x_t)\), giving a realized \(y_t\)
    2. Compute \[ h(x_t, y_t) = \min\left(\frac{\pi(y_t)J(x_t \mid y_t)}{\pi(x_t)J(y_t \mid x_t)}, 1\right) \]
    3. Generate \(U_t \sim \text{Unif}(0,1)\), giving \(u_t\)
    4. If \(u_t < h(x_t, y_t)\), set \(X_{t + 1} = y_t\) else, set \(X_{t+1} = x_t\)

Exercise

Show that the Metropolis-Hastings algorithm preserves detailed balance, when \(\pi(y) > \pi(x)\): \[ \pi(x) K(x, y) = \pi(y) K(y,x) \] where \(K(x,y) = J(y \mid x) h(x, y)\)

Properties of the MH algorithm

One of the remarkable properties of the MH algorithm is that we can choose any pair \(\pi(x), J(y \mid x)\) and we still get draws from \(\pi\). Even so, \(J(y \mid x)\) will impact how quickly the algorithm explores the distribution implied by \(\pi(x)\) i.e. \(P(A) = \int_A \pi(x) dx\)

\[ J(y \mid x) = \ind{0 \leq y \leq 1} \]

# Metropolis algorithm

As we learned in class on Thursday, the Metropolis algorithm requires a symmetric __proposal density__ $J(y \mid x) = J(x \mid y)$.
A generalization of the Metropolis algorithm which doesn't require symmetry is called the Metropolis-Hastings (MH) algorithm. All we do is modify the acceptance probability $h(x, y)$ for a proposed $y$ evaluated at the current value $x$.

In the Metropolis algorithm, for a target density $\pi(x)$ we have:
$$
h(x,y) = \min(\pi(y) / \pi(x), 1)
$$
The Metropolis-Hastings algorithm now has:
$$
h(x,y) = \min\left(\frac{\pi(y)J(x \mid y)}{\pi(x) J(y \mid x)}, 1\right)
$$


We will denote fixed quantities as lower-case numbers, while upper case will represent random variables.

:::{#alg-metro}

## Metropolis-Hastings

For a given $x_1$, $N$, and target density $\pi(x)$:

1. For $t \in \{1, \dots, N\}$
    a. Generate $Y_t \sim J(y \mid x_t)$, giving a realized $y_t$ 
    b. Compute 
    $$
    h(x_t, y_t) = \min\left(\frac{\pi(y_t)J(x_t \mid y_t)}{\pi(x_t)J(y_t \mid x_t)}, 1\right)
    $$
    c. Generate $U_t \sim \text{Unif}(0,1)$, giving $u_t$
    d. If $u_t < h(x_t, y_t)$, set $X_{t + 1} = y_t$ else, set $X_{t+1} = x_t$

:::
